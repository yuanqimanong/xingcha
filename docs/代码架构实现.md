# 星槎 Xīngchá · 代码架构实现

> ## 核心能力
>
> **把一段提示词，变成一个可被任何 OpenAI 客户端直接调用、按用户计量与限额、输出形状有保证、并且随时能带走的服务。**

这句话拆成四个可验证的承诺，每一个都对应本文档中的一个模块——没有归属的承诺就是空话：

| 承诺 | 可验证的表现 | 模块 |
|---|---|---|
| **可被直接调用** | Agent 以 slug 出现在 `GET /v1/models`，Cherry Studio 等客户端下拉框里可见可选，零适配代码 | [5.8 openai_compat](#58-openai_compat--openai-兼容层) |
| **按用户计量与限额** | 每次调用落 token 明细与预估费用；三级主体 × 三窗口配额，超限返回 429 且不穿透 | [5.9 usage / pricing / quota](#59-usage--pricing--quota) |
| **输出形状有保证** | 声明式路径恢复命令式路径的校验能力，并按模型能力分四档标注代价 | [5.4 guarantee](#54-guarantee--四档输出保证) |
| **随时能带走** | 导出三文件目录，在干净环境中零星槎依赖即可运行，校验行为一并保留 | [5.7 exporter](#57-exporter--导出-bundle) |

| 拒绝 | 原因 |

### 2.2 一次调用的生命周期

```
POST /v1/chat/completions   Authorization: Bearer sk-xc-...
  │
  ├─1 AuthService.resolve_token()      令牌 hash 查表 → user_id，禁用即失效
  ├─2 QuotaService.check()             三级主体 × 三窗口，超限 → 429
  ├─3 AgentService.resolve(slug)       slug → agent + current_version
  ├─4 AgentCache.get((id, version))    命中则复用，未命中走 builder
  │     └─ builder.build()             spec_json → AgentSpec → Agent
  │          └─ guarantee.apply()      按档位装配 output_type 与 validator
  ├─5 messages 转换                    OpenAI content parts → pydantic-ai
  ├─6 agent.run(...)                   OTel span 自动上报
  ├─7 usage = result.usage             注意：属性，不是方法
  ├─8 pricing.estimate()               genai_prices.calc_price()
  ├─9 落库 run + run_usage             批量 flush
  └─10 转 OpenAI 响应格式返回
```

### 2.3 进程与并发模型

- **单进程、单事件循环**，无 worker 池、无线程池。目标 1C1G 机器可跑。
- **SQLite WAL**：读并发无锁，写串行化。用量写入批量 flush，不在请求路径上同步落盘。
- **上游并发**：用 pydantic-ai 官方原语 `Agent(max_concurrency=...)`，不自研令牌桶。
- **Agent 实例缓存**：key 为 `(agent_id, version)`。编辑 Agent 产生新版本，旧实例自然淘汰，无需显式失效。
- **长请求**：纯异步，单个 3–30 秒的上游调用不阻塞其它请求。

## 4 数据层

### 4.1 表结构

```sql
-- 系统配置：OpenRouter key 等敏感值 Fernet 加密后存 value_enc
CREATE TABLE setting (
  key         TEXT PRIMARY KEY,
  value_enc   BLOB,
  is_secret   INTEGER NOT NULL DEFAULT 0,
  updated_at  TEXT NOT NULL
);

CREATE TABLE user (
  id            INTEGER PRIMARY KEY,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  role          TEXT NOT NULL CHECK (role IN ('admin','user')),
  is_active     INTEGER NOT NULL DEFAULT 1,
  created_at    TEXT NOT NULL
);

-- 只存 hash 与前缀；明文仅创建时展示一次
CREATE TABLE token (
  id           INTEGER PRIMARY KEY,
  user_id      INTEGER NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  name         TEXT NOT NULL,
  prefix       TEXT NOT NULL,
  hash         TEXT NOT NULL UNIQUE,
  is_active    INTEGER NOT NULL DEFAULT 1,
  expires_at   TEXT,
  last_used_at TEXT,
  created_at   TEXT NOT NULL
);
CREATE INDEX idx_token_hash ON token(hash);

CREATE TABLE agent (
  id                 INTEGER PRIMARY KEY,
  slug               TEXT NOT NULL UNIQUE,   -- 即对外 model id
  name               TEXT NOT NULL,
  description        TEXT,
  is_active          INTEGER NOT NULL DEFAULT 1,
  current_version_id INTEGER,
  created_by         INTEGER REFERENCES user(id),
  created_at         TEXT NOT NULL
);

-- spec_json 整块存 AgentSpec dict，不拆列（决策 2）
CREATE TABLE agent_version (
  id          INTEGER PRIMARY KEY,
  agent_id    INTEGER NOT NULL REFERENCES agent(id) ON DELETE CASCADE,
  version     INTEGER NOT NULL,
  spec_json   TEXT NOT NULL,
  tier        TEXT NOT NULL CHECK (tier IN ('T1','T2','T1P','T3')),
  out_schema  TEXT,                          -- 输出 JSON Schema，null = 纯文本
  changelog   TEXT,
  created_by  INTEGER REFERENCES user(id),
  created_at  TEXT NOT NULL,
  UNIQUE (agent_id, version)
);

CREATE TABLE run (
  id            TEXT PRIMARY KEY,            -- uuid
  agent_id      INTEGER NOT NULL,
  agent_version INTEGER NOT NULL,
  user_id       INTEGER NOT NULL,
  token_id      INTEGER,
  session_id    TEXT,
  tier          TEXT NOT NULL,
  status        TEXT NOT NULL,               -- ok | schema_failed | upstream_error | quota | timeout
  error_code    TEXT,
  latency_ms    INTEGER,
  started_at    TEXT NOT NULL,
  finished_at   TEXT
);
CREATE INDEX idx_run_user_time  ON run(user_id, started_at);
CREATE INDEX idx_run_agent_time ON run(agent_id, started_at);

-- 字段对齐 pydantic-ai 的 RunUsage
CREATE TABLE run_usage (
  run_id             TEXT PRIMARY KEY REFERENCES run(id) ON DELETE CASCADE,
  model              TEXT NOT NULL,
  input_tokens       INTEGER NOT NULL DEFAULT 0,
  output_tokens      INTEGER NOT NULL DEFAULT 0,
  cache_read_tokens  INTEGER NOT NULL DEFAULT 0,
  cache_write_tokens INTEGER NOT NULL DEFAULT 0,
  requests           INTEGER NOT NULL DEFAULT 0,
  tool_calls         INTEGER NOT NULL DEFAULT 0,
  schema_retries     INTEGER NOT NULL DEFAULT 0,   -- 因 schema 违规重试的次数
  cost_usd           REAL,
  cost_source        TEXT                           -- genai_prices | upstream | unknown
);

CREATE TABLE quota (
  id           INTEGER PRIMARY KEY,
  subject_type TEXT NOT NULL CHECK (subject_type IN ('user','token','agent')),
  subject_id   INTEGER NOT NULL,
  window       TEXT NOT NULL CHECK (window IN ('day','month','total')),
  limit_usd    REAL,
  limit_requests INTEGER,
  UNIQUE (subject_type, subject_id, window)
);
```

> `schema_retries` 单独成列，而非混入 `requests`——这是[护栏](#54-guarantee--四档输出保证)要求的可观测指标：坏 schema 会静默烧钱，必须能被单独查询和告警。

### 4.2 引擎与 WAL

```python
# src/xingcha/db/engine.py
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine
from sqlalchemy import event

def make_engine(db_path: str):
    engine = create_async_engine(f"sqlite+aiosqlite:///{db_path}", echo=False)

    @event.listens_for(engine.sync_engine, "connect")
    def _pragmas(dbapi_conn, _):
        cur = dbapi_conn.cursor()
        cur.execute("PRAGMA journal_mode=WAL")     # 读写不互斥
        cur.execute("PRAGMA synchronous=NORMAL")   # WAL 下安全且快
        cur.execute("PRAGMA foreign_keys=ON")
        cur.execute("PRAGMA busy_timeout=5000")
        cur.close()

    return engine, async_sessionmaker(engine, expire_on_commit=False)
```

### 4.3 迁移

Alembic，启动时自动 `upgrade head`。**不使用 autogenerate 直接上生产**——每个迁移脚本手工审阅，因为 SQLite 的 `ALTER TABLE` 能力有限，列变更需走「建新表 → 拷数据 → 换名」。

## 5 核心模块

每个模块按 **职责 → 接口 → 核心代码 → 失败模式** 描述。代码为设计稿，签名与 pydantic-ai 2.35.3 实测 API 一致。

### 5.1 config · 配置

单一配置入口，全部来自环境变量或 `data/` 目录，**不读配置文件**（C3：三条命令上手，中间不插入配置文件编辑）。

```python
# src/xingcha/config.py
from pathlib import Path
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="XINGCHA_", env_file=".env")

    data_dir: Path = Path("./data")
    host: str = "127.0.0.1"          # 默认只监听本地，暴露需显式 --host
    port: int = 8720

    secret_key: str | None = None     # 缺失则首启生成 data/secret.key 并 chmod 600
    openrouter_base_url: str = "https://openrouter.ai/api/v1"

    langfuse_otlp_endpoint: str | None = None   # 不配也能跑
    langfuse_public_key: str | None = None
    langfuse_secret_key: str | None = None

    max_concurrency: int = 16
    default_request_timeout: float = 600.0      # 长思考模型

    @property
    def db_path(self) -> Path: return self.data_dir / "xingcha.db"
    @property
    def secret_path(self) -> Path: return self.data_dir / "secret.key"
```

> OpenRouter API key **不在此处**——它由管理员在 Web 上填写，Fernet 加密后存 `setting` 表。放进环境变量会让"Web 表单配置"这条主线断掉。

### 5.2 builder · 从数据库行到 Agent

**职责**：`agent_version.spec_json` → `AgentSpec` dict → `Agent` 实例。

**这是上游版本适配的唯一集中点**。pydantic-ai 的 `AgentSpec` 字段与 `CAPABILITY_TYPES` 会随版本演进，所有兼容处理只写在这个文件里，升级时只需改这里（决策 2 的直接收益）。

> **实测踩坑**：`OpenRouterProvider` 的构造签名是
> `(*, api_key, app_url, app_title, openai_client, http_client)`——**没有 `base_url` 参数**。
> 而大陆中转恰恰必须改 base_url。正确做法是自建 `AsyncOpenAI` 指向中转，再传给
> `OpenRouterProvider(openai_client=...)`：这样既走中转，又保留 OpenRouter 的
> model profile（[判档](#54-guarantee--四档输出保证)依赖它）。
> 注意此时 `provider.base_url` 属性仍报告官方地址，实际生效的是 `client.base_url`——
> 属性有误导性但不影响行为，排查时别被它带偏。

```python
# src/xingcha/core/builder.py
from dataclasses import dataclass
from functools import lru_cache

from openai import AsyncOpenAI
from pydantic_ai import Agent
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.openrouter import OpenRouterProvider

from .guarantee import Tier, apply_guarantee

@dataclass(frozen=True)
class UpstreamConfig:
    api_key: str
    base_url: str            # 官方地址，或新加坡中转地址
    app_url: str | None = None
    app_title: str | None = "Xingcha"

@dataclass
class BuildResult:
    agent: Agent
    tier: Tier
    out_schema: dict | None
    retry_counter: dict      # 由 guarantee 写入，RunService 落 schema_retries

def make_provider(cfg: UpstreamConfig) -> OpenRouterProvider:
    """OpenRouterProvider 不接受 base_url，只能通过自建 client 注入。"""
    headers = {}
    if cfg.app_url:   headers["HTTP-Referer"] = cfg.app_url
    if cfg.app_title: headers["X-Title"] = cfg.app_title
    client = AsyncOpenAI(
        base_url=cfg.base_url,
        api_key=cfg.api_key,
        default_headers=headers or None,
    )
    return OpenRouterProvider(openai_client=client)

def build(
    spec_json: dict,
    *,
    tier: Tier,
    out_schema: dict | None,
    provider: OpenRouterProvider,
    max_concurrency: int,
) -> BuildResult:
    """spec_json 原样来自数据库，不在别处解释其字段含义。"""
    spec = dict(spec_json)

    # output_schema 交给 from_spec 会退化成不校验的 StructuredDict，
    # 必须摘出来由 guarantee 接管——这一行是卖点乙成立的前提。
    spec.pop("output_schema", None)

    model = OpenAIChatModel(_strip_prefix(spec.pop("model")), provider=provider)

    agent = Agent.from_spec(
        spec,
        model=model,
        max_concurrency=max_concurrency,
        custom_capability_types=_custom_capabilities(),
    )
    counter = apply_guarantee(agent, tier=tier, out_schema=out_schema)
    return BuildResult(agent=agent, tier=tier, out_schema=out_schema, retry_counter=counter)

def _strip_prefix(m: str) -> str:
    # 表单存 "openrouter:openai/gpt-5"；provider 已显式给出，去掉前缀
    return m.split(":", 1)[1] if m.startswith("openrouter:") else m

@lru_cache(maxsize=1)
def _custom_capabilities() -> tuple[type, ...]:
    return ()   # Alpha 后：MCP 逃生舱相关的自定义 capability
```

**Provider 复用**：`AsyncOpenAI` 内含连接池，**每个 Agent 各建一个会浪费连接**。provider 按 `UpstreamConfig` 缓存一份，全局复用；管理员改 key 或中转地址时整体重建。

**失败模式**：`from_spec` 遇未知 capability 名会抛 `ValueError` 并列出合法选项。builder 需捕获并转成[错误契约](#6-错误契约)中的 `agent_spec_invalid`，不让 500 泄漏给用户。

### 5.3 models_catalog · 上游模型能力目录

**职责**：拉取并缓存 OpenRouter `/v1/models` 的 `supported_parameters`，供 [guarantee](#54-guarantee--四档输出保证) 判档与表单渲染。

实测依据（2026-08-28 快照）：381 个模型中 295 个含 `structured_outputs`，86 个不含。**目录随时变动，因此判档必须运行时查询，不可硬编码模型名单。**

```python
# src/xingcha/core/models_catalog.py
import time

class ModelsCatalog:
    _TTL = 3600

    def __init__(self, http, base_url: str):
        self._http, self._base = http, base_url
        self._cache: dict[str, set[str]] = {}
        self._at = 0.0

    async def refresh(self, api_key: str) -> None:
        r = await self._http.get(
            f"{self._base}/models", headers={"Authorization": f"Bearer {api_key}"}
        )
        r.raise_for_status()
        self._cache = {
            m["id"]: set(m.get("supported_parameters") or []) for m in r.json()["data"]
        }
        self._at = time.monotonic()

    def supports_native_schema(self, model_id: str) -> bool:
        """未知模型保守判定为不支持——宁可降级到 T2，不可假装有保证。"""
        return "structured_outputs" in self._cache.get(model_id, set())

    def is_stale(self) -> bool:
        return time.monotonic() - self._at > self._TTL
```

> **保守判定原则**：模型不在目录里时返回 `False`。宁可降级到 T2 多花点重试成本，也不能对用户谎称有原生保证。

### 5.4 guarantee · 四档输出保证

★ **本项目的技术核心**，卖点乙的全部实现。设计依据见前期调研 [8.4](前期调研.md#84-决策-4--分级输出保证与导出-bundle) 与 [12.2](前期调研.md#122-最重要的发现约束解码不是免费的)。

**要解决的问题**：`AgentSpec.output_schema` 经 `StructuredDict` 只作提示，**不做运行时校验**（实测：缺必填、类型错、超 maxItems 全部放行，`retries` 不触发）。而命令式路径用真 Pydantic model 时**会**校验并重试。星槎要在声明式路径上恢复这个保证。

**四档到 pydantic-ai 的映射**——官方已提供输出模式 marker 类，无需手写 `extra_body`：

| 档 | pydantic-ai 表达 | 形状保证 | 内容风险 | 成本 |
|---|---|---|---|---|
| **T1** | `NativeOutput(StructuredDict(schema), strict=True)` + 校验断言 | 最强 | 有对齐税 | 单次 |
| **T2** | `ToolOutput(StructuredDict(schema))` + `output_validator` + jsonschema | 强 | 无对齐税 | 重试放大 |
| **T1+** | 两阶段：自由推理 → 再以 T1 格式化 | 最强 | 最低 | 约两倍 |
| **T3** | `PromptedOutput(StructuredDict(schema))` | 无 | 无 | 单次 |

```python
# src/xingcha/core/guarantee.py
from enum import StrEnum
import jsonschema
from pydantic_ai import (
    Agent, ModelRetry, NativeOutput, PromptedOutput, StructuredDict, ToolOutput,
)

class Tier(StrEnum):
    T1  = "T1"    # 原生约束解码
    T2  = "T2"    # 校验后重试
    T1P = "T1P"   # 两阶段：自由推理 → 格式化
    T3  = "T3"    # 仅提示词

class SchemaViolation(Exception):
    """校验重试耗尽。携带最后一次错误，供错误契约与可观测使用。"""
    def __init__(self, message: str, retries: int):
        super().__init__(message)
        self.retries = retries

def output_spec(tier: Tier, schema: dict):
    """把档位翻译成 pydantic-ai 的 output_type。"""
    sd = StructuredDict(schema)
    match tier:
        case Tier.T1 | Tier.T1P: return NativeOutput(sd, strict=True)
        case Tier.T2:            return ToolOutput(sd)
        case Tier.T3:            return PromptedOutput(sd)

def apply_guarantee(
    agent: Agent, *, tier: Tier, out_schema: dict | None
) -> dict[str, int]:
    """挂载运行时校验，返回重试计数器（调用方落库用）。

    T3 不挂校验；T1 挂断言式校验（正常永不触发）；T2/T1+ 挂重试式校验。
    计数器由闭包持有并返回，不往 Agent 上挂私有属性。
    """
    counter = {"schema_retries": 0, "provider_noncompliance": 0}
    if out_schema is None or tier is Tier.T3:
        return counter

    validator = jsonschema.Draft202012Validator(out_schema)

    @agent.output_validator
    def _validate(data):
        errors = sorted(validator.iter_errors(data), key=lambda e: list(e.absolute_path))
        if not errors:
            return data

        counter["schema_retries"] += 1
        if tier is Tier.T1:
            # 原生约束下仍违规 = 上游未兑现 strict。单独计数以便告警，
            # 但依然重试，绝不把脏数据交给调用方。
            counter["provider_noncompliance"] += 1

        detail = "; ".join(
            f"{'/'.join(map(str, e.absolute_path)) or '<root>'}: {e.message}"
            for e in errors[:5]
        )
        raise ModelRetry(f"输出不符合 schema：{detail}")

    return counter
```

**两阶段（T1+）的执行**在 RunService 而非此处——它需要两次模型调用，属于编排职责：

```python
# services/run.py 片段
async def _run_two_stage(build, prompt, *, usage_limits):

    # 阶段二：只做格式化，此时才施加 T1 原生约束

```

**护栏**——重试会放大 token 与费用，坏 schema 会静默烧钱：

**判档逻辑**——保存 Agent 时执行，结果写入 `agent_version.tier`：

```python
def resolve_tier(requested: Tier | None, model_id: str, catalog, has_schema: bool) -> tuple[Tier, str | None]:
    if not has_schema:
        return Tier.T3, None
    native_ok = catalog.supports_native_schema(model_id)
    if requested in (Tier.T1, Tier.T1P) and not native_ok:
        return Tier.T2, f"{model_id} 不支持原生结构化输出，已降级为 T2（校验后重试）"
    return requested or (Tier.T1 if native_ok else Tier.T2), None
```

**失败模式**

| 情况 | 行为 |
|---|---|
| T2 重试耗尽 | pydantic-ai 抛 `UnexpectedModelBehavior`，转 `SchemaViolation` → 错误契约 `schema_violation`，HTTP 422 |
| T1 下仍违规 | 记 `provider_noncompliance` 指标并重试。这是上游未兑现 `strict` 的证据，值得单独告警 |
| schema 本身非法 | 保存时即被 [schema_guard](#56-schema_guard--schema-安全护栏) 拦下，不进运行时 |

### 5.5 schema_lint · 字段命名 lint

依据文献：在 prompt、模型、结构、解码设置全部固定的前提下，**仅改 schema 字段措辞就能显著影响准确率**，且效应因模型而异。

**这是只有"表单建 Agent"这种形态才方便提供的功能**——用户正在表单里敲字段名，此时给建议成本最低。实现是一组规则，不调模型。

```python
# src/xingcha/core/schema_lint.py
from dataclasses import dataclass
import re

@dataclass
class Hint:
    path: str
    level: str          # warn | info
    message: str

_ABBR = re.compile(r"^[a-z]{1,3}\d*$", re.I)
_GENERIC = {"data", "value", "val", "result", "output", "item", "obj", "info", "content", "field"}

def lint(schema: dict, path: str = "") -> list[Hint]:
    hints: list[Hint] = []
    for key, sub in (schema.get("properties") or {}).items():
        here = f"{path}/{key}" if path else key
        if _ABBR.match(key):
            hints.append(Hint(here, "warn", f"「{key}」过短，模型难以推断含义。建议用完整语义词"))
        if key.lower() in _GENERIC:
            hints.append(Hint(here, "warn", f"「{key}」语义空泛，建议改为描述实际内容的名称"))
        if not sub.get("description"):
            hints.append(Hint(here, "info", f"「{key}」缺少 description。字段描述是一条有效的指令通道"))
        if sub.get("type") == "object":
            hints.extend(lint(sub, here))
    return hints
```

前端在表单保存时展示提示，**不阻断保存**——这是建议不是规则。

### 5.6 schema_guard · schema 安全护栏

对应风险 R11。用户提交的 JSON Schema 会被透传为解码约束，而文献证明**良性 grammar 约束即可成为越狱攻击面**。此前的安全模型只考虑了"不执行用户 Python"，遗漏了这一层。

```python
# src/xingcha/core/schema_guard.py
MAX_DEPTH, MAX_PROPS, MAX_ENUM, MAX_BYTES = 8, 120, 200, 64 * 1024

class SchemaRejected(ValueError): ...

def validate_schema(schema: dict, raw_len: int) -> None:
    if raw_len > MAX_BYTES:
        raise SchemaRejected(f"schema 超过 {MAX_BYTES // 1024}KB")
    if "$ref" in _flatten_keys(schema):
        raise SchemaRejected("不支持 $ref / $defs（StructuredDict 亦不支持递归引用）")
    _walk(schema, depth=0, props=[0])

def _flatten_keys(node) -> set[str]:
    """递归收集所有出现过的 key，用于检测 $ref / $defs。"""
    out: set[str] = set()
    if isinstance(node, dict):
        out |= set(node)
        for v in node.values():
            out |= _flatten_keys(v)
    elif isinstance(node, list):
        for v in node:
            out |= _flatten_keys(v)
    return out

def _walk(node: dict, *, depth: int, props: list[int]) -> None:
    if depth > MAX_DEPTH:
        raise SchemaRejected(f"嵌套深度超过 {MAX_DEPTH}")
    for key, sub in (node.get("properties") or {}).items():
        props[0] += 1
        if props[0] > MAX_PROPS:
            raise SchemaRejected(f"字段总数超过 {MAX_PROPS}")
        if len(sub.get("enum") or []) > MAX_ENUM:
            raise SchemaRejected(f"「{key}」的 enum 超过 {MAX_ENUM} 项")
        if sub.get("type") == "object":
            _walk(sub, depth=depth + 1, props=props)
```

**边界说明**：这只防资源耗尽与已知的病态结构，**不声称能防住语义层面的越狱**。真正的缓解在于星槎不做代码生成场景，且 schema 由管理员而非终端用户提交——两道自然屏障。文档必须如实标注这一点，不夸大防护能力。

```python
async def check(self, *, user, token, agent) -> None:
    for subject_type, subject_id in (("user", user.id), ("token", token.id), ("agent", agent.id)):
        for row in await self._rules(subject_type, subject_id):
            spent = await self._spent(subject_type, subject_id, row.window)
            if row.limit_usd is not None and spent.usd >= row.limit_usd:
                raise QuotaExceeded(subject_type, row.window, "usd")
            if row.limit_requests is not None and spent.requests >= row.limit_requests:
                raise QuotaExceeded(subject_type, row.window, "requests")
```

**并发不穿透**：配额检查与用量累加在同一 SQLite 事务内（`BEGIN IMMEDIATE`）。Alpha 验收标准之一是 50 并发下不穿透。

### 5.10 web · 表单

Jinja2 + HTMX，静态文件内嵌进 wheel，**不走 CDN**（离线可用 + 无外部依赖）。

Agent 配置表单分区与 `AgentSpec` 一一映射，两处星槎自有增强：

| 分区 | 增强 |
|---|---|
| 输出 | 字段编辑器实时调用 [schema_lint](#55-schema_lint--字段命名-lint)，用 HTMX 局部刷新提示 |
| 模型 | 选中模型后显示**可用保证档位与代价**，由 [models_catalog](#53-models_catalog--上游模型能力目录) 驱动 |

能力勾选项**运行时从 `CAPABILITY_TYPES` 读取**，不硬编码——官方新增能力自动出现：

```python
# src/xingcha/core/capabilities.py
from pydantic_ai.capabilities import CAPABILITY_TYPES

def declarable() -> list[str]:
    """当前 pydantic-ai 版本支持在 spec 中声明的能力名。"""
    return sorted(CAPABILITY_TYPES)
```

### 5.11 mcp_host · 逃生舱（Alpha 后）

决策 1：自定义 Python 工具走**本地 MCP server**，而非进程内 `python:` 引用。

理由：`MCP` 是官方可声明能力，因此**导出的 YAML 仍是 100% 纯净的 pydantic-ai spec**，不破坏卖点甲；同时用户代码运行在独立进程，崩溃不拖垮网关；工具还能被 Claude Code、Cursor 等任意 MCP 客户端复用。

Web 表单**只提供符号选择，绝不接受用户提交的 Python 代码**——在管理后台执行任意 Python 等于把它变成 RCE 入口。代码放在服务器可 import 的位置，`xingcha ext scan` 发现，部署即审计、git 即版本管理。

## 6 错误契约

统一 OpenAI 风格，`type` 为闭集，便于客户端与监控消费。

```python
def err(code: str, message: str, **extra) -> dict:
    return {"error": {"message": message, "type": code, "code": code, **extra}}
```

| type | HTTP | 触发 |
|---|---|---|
| `invalid_api_key` | 401 | 令牌无效、禁用、过期 |
| `quota_exceeded` | 429 | 配额超限，附 `subject_type` / `window` |
| `model_not_found` | 404 | slug 不存在或已停用 |
| `stream_unsupported` | 400 | 结构化 Agent 请求 `stream=true` |
| `schema_violation` | 422 | T2 重试耗尽，附 `retries` 与最后错误 |
| `agent_spec_invalid` | 500 | spec 无法构造（通常是上游版本变动），需管理员介入 |
| `upstream_error` | 502 | OpenRouter 报错，透传上游状态码 |
| `upstream_timeout` | 504 | 超过 `request_timeout` |
