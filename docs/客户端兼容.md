# 客户端兼容矩阵

星槎的对外面是 OpenAI 兼容 API，所以"哪些客户端能直接用"是一个可以被验证的问题。
这份文档**严格区分已验证与未验证**——把"应该能用"写成"能用"是这类矩阵最常见的
失真方式，而它恰好在你最需要它准确的时候误导你。

## 已验证（自动化，每次 CI 都跑）

### OpenAI Python SDK 3.7.0 ✅

`tests/test_openai_sdk.py` 起一个**真实的 HTTP 服务**并用 `openai.OpenAI` 打它。
这不是拿 TestClient 打 ASGI——SDK 会按自己的 pydantic 模型校验响应、自己拼 URL、
自己分帧 SSE。响应里少一个 `created` 字段，TestClient 毫不在意，SDK 直接抛 APIError。

| 能力 | 结果 |
|---|---|
| `client.models.list()` 列出 Agent 与上游模型 | ✅ |
| Agent 行排在最前（部分客户端取 `data[0]` 当默认模型） | ✅ |
| `client.models.retrieve("<slug>")` | ✅ |
| 调用裸模型 `openai/gpt-5` | ✅ |
| 调用 Agent 并 `json.loads(content)` 取回结构化结果 | ✅ |
| Agent 流式（v0.4 起真 delta，帧形状未变） | ✅ |
| 裸模型流式（字节透明转发） | ✅ |
| 404 / 422 / 400 / 401 被 SDK 正确分派成 `APIStatusError` | ✅ |
| `x_xingcha` 扩展块不破坏 SDK 解析 | ✅ |

**业务代码要改的就是这两行：**

```python
from openai import OpenAI
client = OpenAI(base_url="https://xc.example.com/v1", api_key="sk-xc-1-...")
```

> ⚠️ **如果你机器上设了 socks 代理**（`ALL_PROXY=socks5://...`），openai SDK 会在
> **构造阶段**就抛 `ImportError: Using SOCKS proxy, but the 'socksio' package is
> not installed`。这跟星槎无关，是 SDK 默认 `trust_env=True` 读到了机器代理。
>
> 而把 `base_url` 指向星槎之后你本来就不需要那个代理了——把它从环境里去掉即可。
> 非要保留的话，给 SDK 传一个 `http_client=httpx.Client(trust_env=False)`。

### curl / 任意 HTTP 客户端 ✅

`/v1` 下所有非自有路径**字节级反代**到上游，所以 OpenRouter 有的能力星槎都有，
包括本文档写作时还不存在的那些。已验证 `/v1/embeddings` 透明可用。

## 未验证 ⚠️

下面这些**没有实测过**。它们是桌面/浏览器应用，装不进 CI，而我不想把推断写成结论。

| 客户端 | 预期 | 未验证的原因 |
|---|---|---|
| Cherry Studio | 应当可用 | 桌面应用，需要人工操作 |
| Open WebUI | 应当可用，但**浏览器直连需要 CORS** | 见下方说明 |
| Continue（VS Code） | 应当可用 | IDE 插件 |
| Cursor | 应当可用 | 桌面应用 |

"应当可用"的依据是：这些客户端都走 `GET /v1/models` + `POST /v1/chat/completions`，
而这两个端点已用真实 SDK 验证过。但**依据不等于验证**——真到了那一步可能卡在
某个具体客户端的怪癖上（比如它要求 `owned_by` 是某个特定值，或者对 `created=0`
有意见）。

### 浏览器直连的客户端要额外配 CORS

Open WebUI 这类跑在浏览器里的客户端，请求前会发 CORS 预检。星槎**默认不发任何
CORS 头**（`XINGCHA_CORS_ORIGINS` 默认为空），所以浏览器直连会被拦。

放开的办法：

```env
XINGCHA_CORS_ORIGINS=https://webui.example.com
```

默认最严是有意的：放开 origin 是纯加法，而默认放开之后再收紧就是破坏性变更。
`OPTIONS` 请求由星槎自己应答、**永不反代**（否则预检会由 OpenRouter 的策略决定，
表现为"非流式偶尔能用、浏览器直连必挂"）。

## 自己验一个客户端

装好之后填两个值：

```
API 地址 / Base URL    https://xc.你的域名/v1
API Key                sk-xc-1-...
```

然后逐条对：

1. **模型列表能拉出来吗** —— 拉不出来看 `xingcha doctor` 与
   `curl https://<域名>/v1/models -H "Authorization: Bearer sk-xc-..."`
2. **Agent 出现在下拉框里吗** —— 这是星槎相对 OpenRouter Presets 的关键差别：
   Presets 可以被调用，但实测**不出现在** `GET /v1/models` 里
3. **纯文本 Agent 能聊吗**（含流式）
4. **结构化 Agent 呢** —— 它的 `content` 是一段 JSON 文本。聊天类客户端会把它
   当普通文本显示，那是正常的：结构化 Agent 本来就是给业务代码用的，不是给人聊天的

验过之后欢迎把结果补进上面那张表——**连同版本号**。客户端行为在版本之间会变，
一条没有版本号的"可用"结论过几个月就不可信了。

## 一处已知的、不会修的差异

**结构化 Agent 不支持 `stream=true`**，会返回 400 `stream_unsupported`。

流一半的 JSON 无法被安全解析，所以这里选择诚实报错而不是假装支持。要流式就用
纯文本 Agent。

这条**不会**改：把它变成"能流"需要在服务端缓冲完整输出再一次性吐出去，那不是
流式，只是把等待藏起来。
