调用追踪

把每次调用的完整消息、重试与耗时按 OTLP 协议上报到一个追踪后端，用来看 模型实际收到了什么、又返回了什么。 调用记录页只有次数、费用与错误，没有消息内容。

这里只填地址，开关在每个 Agent 上。 填好之后到 Agent 编辑页的「可观测」分区逐个勾选——哪些 Agent 的对话内容可以 离开这台机器，通常不是一个全局答案。

要填 OTLP/HTTP 的 traces 入口，不是后端的网页地址。 留空即关闭，两把 key 也会一起清掉。
自建 Langfusehttp://<主机:端口>/api/public/otel/v1/traces
同一 docker 网络http://langfuse-web:3000/api/public/otel/v1/traces
Langfuse 托管版https://cloud.langfuse.com/api/public/otel/v1/traces
OTel Collector / Jaegerhttp://<主机>:4318/v1/traces
自建的地址可以是内网 IP 或容器名（私有网段是放行的），但云元数据地址会被拒。
只有 Langfuse 需要这两把 key（它用 Basic 认证）。 填 OTel Collector / Jaeger 这类不校验身份的后端就留空。
