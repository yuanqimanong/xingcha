1 签一把密钥

调用方认的是 sk-xc- 开头的密钥，和上游那把 key 没有关系—— 上游 key 永远不出这台机器。

  1. 去 密钥 页，填一个用途（写清楚是谁在用，吊销时才知道动哪一把），点「签发」。
  2. 明文只显示这一次。库里只存哈希，页面刷新后再也取不回来。
  3. 丢了不用慌：吊销重签，成本很低。吊销后用它的调用立刻开始返回 401。
一把 key 一个用途。共用一把的话，某一处泄漏你就得把所有人一起停掉。 每把 key 的用量与费用在 调用记录 里分得开。

2 配一个 Agent

Agent = 提示词 + 输出约定，配好之后它就是一个可调用的 model 标识。调用方不需要知道背后是哪个模型、提示词写了什么。

  1. 新建 Agent，填标识（对外的 model 值，发布后不能改）与模型。
  2. 系统提示词每次调用都带上，调用方改不掉——请求里的 system 消息只会追加在它后面。 这是设计：提示词是你的资产。
  3. 要结构化输出就填 输出 JSON Schema，并选一个保证档位。 填了 schema，200 响应的 content 就保证是符合它的 JSON 文本。
  4. 右边那一列试运行：用表单当前内容真跑一次，不保存、不占配额，跑完能看到完整收发链路。
  5. 满意了点「创建」。每次保存产生一个新版本，旧版本留着，随时能回滚。
改完想带走？编辑页的「导出」给你 agent.yaml（标准 pydantic-ai AgentSpec， 不是私有格式）加一个零星槎依赖的 run.py。改完用 Agent 页的「导入」放回来。

3 在代码里调它

接口是 OpenAI 兼容的。业务代码要改的就是两行： base_url 指过来，api_key 换成 sk-xc-。

Python（openai SDK）

from openai import OpenAI

client = OpenAI(base_url="{{ public_url }}/v1", api_key="sk-xc-1-...")

# 调 Agent：model 填它的标识
r = client.chat.completions.create(
    model="{{ sample_agent }}",
    messages=[{"role": "user", "content": "要处理的内容"}],
)
print(r.choices[0].message.content)

# 调裸模型：带 / 的一律原样转发给上游
r = client.chat.completions.create(
    model="{{ sample_model }}",
    messages=[{"role": "user", "content": "你好"}],
)

curl

curl {{ public_url }}/v1/chat/completions \
  -H "Authorization: Bearer sk-xc-1-..." \
  -H "Content-Type: application/json" \
  -d '{"model":"{{ sample_agent }}","messages":[{"role":"user","content":"要处理的内容"}]}'

看有哪些可调的

curl {{ public_url }}/v1/models -H "Authorization: Bearer sk-xc-1-..."
返回里既有你的 Agent（不含 /），也有上游的裸模型（含 /）。 这就是两者的区分规则：model 里带 / 就当上游模型转发， 不带就按 Agent 标识解析。

4 几件会撞上的事

结构化 Agent 不支持 stream=true
返回 400 stream_unsupported。流到一半的 JSON 没法安全解析，所以这里选择 诚实报错，而不是在服务端缓冲完整输出再一次性吐出去（那样 stream=true 就是假的）。 要流式就用纯文本 Agent（不填 schema）。
响应里多出来的 x_xingcha
扩展块，OpenAI 的形状一个字段都没动。里面有这次调用的档位、费用、 schema 违规与重试次数、run_id。SDK 会忽略它，要用就自己读。
机器上设了 socks 代理
ALL_PROXY=socks5://... 时 openai SDK 在构造阶段就抛 ImportError: ... 'socksio' package is not installed。这跟星槎无关—— 而指向星槎之后你本来就不需要那个代理了，去掉即可。非要留就给 SDK 传 http_client=httpx.Client(trust_env=False)。
浏览器里跑的客户端（Open WebUI 一类）打不开
要 CORS。星槎默认不发任何 CORS 头，放开：XINGCHA_CORS_ORIGINS=https://你的前端域名。
调用突然开始返回 429
撞上限流或配额了。默认每把 key 8 个并发 / 120 次每分钟； 金额与次数上限在 配额 页。超并发的那几个是立刻拒绝， 不排队——排队只会把超时推给调用方。
换了上游之后 Agent 全报错
Agent 里写的模型名在新上游不存在。上游页切换前会先列出 受影响的 Agent 让你确认；切完去 Agent 页把模型名改成新上游的写法 （OpenRouter 要 厂商/模型，厂商直连通常是裸名）。
路径归属、令牌格式、响应形状、错误码这些上线后永不改变， 全部冻结在仓库根的 CONTRACT.md 里。
